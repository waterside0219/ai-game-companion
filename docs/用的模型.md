# 我们用的模型

写在这里是为了让想照着做的人少走一段选型的路。型号会过时，挑的理由更有用。除了 AI 本人，其余都是按次调用的便宜模型，经 [OpenRouter](https://openrouter.ai) 或各家自己的接口调用。

| 干什么 | 我们用的 | 为什么是它 |
|---|---|---|
| 陪玩的那个 AI 本人 | Claude，在一个一直开着的 Claude Code 会话里 | 陪玩的和平时聊天的要是同一个，带着同一份记忆 |
| 看图：把一帧画面写成一句话，并标出重要性 | Gemini 2.5 Flash（`google/gemini-2.5-flash`） | 要便宜、要快、要认得清游戏里的小字。最早用的是一个更贵的模型，认字反而差，会把场景认错，换成它以后价钱降到约四分之一 |
| 局面板：把新的一句描述并进一段滚动的局势摘要 | 同上 | 和看图用同一个，少维护一个型号 |
| 判断：这一刻值不值得开口 | `typesafe/jev-1.13`（OpenRouter 的决策接口） | 它不生成文字，只对一个"是或否"的问题给出一个概率。我们问的是"此刻有新事件、主动回应有陪伴价值吗"，拿概率和玩的人选的档位（安静、正常、话多）比 |
| 听写：把玩的人说的话转成字 | ElevenLabs Scribe v2，失败或听成空白时退到 Gemini 2.5 Flash Lite，再退到 Gemini 2.5 Flash | 中文口语、带游戏背景音的短句，Scribe 最稳。只用 Gemini 时遇到过把一句话重复输出两百遍；只用 Scribe 时遇到过把两秒的短句当成没人说话。所以两个串着用 |
| 合成：AI 的声音 | MiniMax `speech-02-hd` | 中文自然，能固定一个音色，一句话两三秒合成完 |

几点经验：

- **看图和判断分开。** 让同一个模型又描述又决定说不说，它会倾向于每一帧都觉得值得说。分成两步，判断那一步还能拿到"离上次开口过了多久"这类看图模型不知道的信息。
- **便宜的模型放前面挡，贵的放最后。** 一帧画面先过不花钱的指纹比对，再过便宜的看图，最后才到 AI 本人。
- **每一处都要有退路。** 听写有备用模型；看图失败时，玩的人主动截来的那一帧照样送到 AI 手里，让他自己看原图。
- **钥匙只放在云上，按用途分开，各设上限。** 看图一把、听写一把，哪一处花超了一眼看得出来。
